The problem with those numbers

Every one of them is somebody else's average.

They tell you the category is riskier. They cannot tell you whether your agent-written code is failing more than your human-written code, which service it concentrates in, or whether last quarter's review policy actually moved it. No engineering leader can currently answer that. The data to answer it is already sitting in your git history.

Method

Attribution you already have, measured honestly.

Every agentic coding tool stamps a Co-Authored-By trailer by default, and git trailers survive rebase. Provenance is already recorded in history you already own — which is why the first report needs no instrumentation and no access to your code.

TF

Attribution anchored on identity, never a keyword

Trailers are parsed with git's own rule — the final paragraph only, and only when every line in it is trailer-shaped — then matched against known vendor identities. An engineer named Claudia is never scored as a machine. One false positive discredits the whole report with the team being measured.

F

Remediation does not count as risk

A fix is the response to a failure, not a new unit of one. Scoring fixes as subjects flatters whichever cohort happens to do the cleanup, so they are excluded from the denominator.

S

High-traffic files cannot link two changes

A lockfile touched by every commit carries no signal about whether any one change failed. Lockfiles, and any file touched by more than a quarter of commits, are excluded from overlap matching.

W

A sweeping fix cannot convict

fix lint across four hundred files is maintenance, not the remediation of any single change. On our own test repository this one rule moved the measured rework rate from 71.7% to 21.7% — the difference between a fabricated alarm and a usable number.

WNA

It says when it does not know

Below thirty scored commits in either cohort, the report prints LOW CONFIDENCE instead of a ratio. A number that overstates its own certainty is worse than no number, in a product whose only real asset is being believed.

Where this is weak

Stated up front, because you would find out anyway.

  • Revert-or-rework is a proxy for change failure rate, not a measurement of it. Join your own incident data before running policy off the number.
  • Commits without trailers count as human-authored, so the load line is a floor, not an estimate.
  • Squash-merge workflows collapse many changes into one commit and coarsen the analysis.
  • We never report on named individuals. Cohorts are machine versus human — never person versus person, and not as a configurable setting.
